# Contributing

Pull requests are welcome. I maintain this project as time permits, so I may not respond straight away. A delay does not mean that I have dismissed the report or patch.

## Before opening an issue

- Search open and closed issues. Add useful information to an existing issue instead of creating a duplicate.
- Use one issue for one bug or proposal.
- Remove private journal text, paths, and account details from examples.

A bug report should include:

- the app version and macOS version;
- steps that reproduce the problem;
- what you expected and what happened;
- a minimal, sanitized journal file when the file content matters.

For a feature request, describe the workflow that is difficult and the result you need. This makes the request easier to assess than a proposed interface alone.

## Pull requests

Keep each pull request focused. Explain the behavior it changes, add or update tests where practical, and run the checks listed in the README.

Journal files are the project's public data format. Discuss changes to their names or contents in an issue before implementing them.
